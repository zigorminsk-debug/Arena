# Arena Mobile

Android-приложение для удобного использования **[arena.ai](https://arena.ai)** с телефона:
мгновенное переключение между аккаунтами, подключение GitHub для Agent Mode,
сборка APK автоматически на GitHub Actions.

> Это неофициальная WebView-оболочка. Данные остаются на устройстве: нет аналитики,
> рекламы и сторонних SDK.

---

## Скачать APK

1. Откройте вкладку **[Releases](../../releases)** — там лежат готовые APK, собранные автоматически.
2. Либо возьмите артефакт последнего запуска: **[Actions](../../actions/workflows/build-apk.yml)** →
   нужный run → раздел **Artifacts** → `ArenaMobile-APK-…`.

Установка: скачайте APK на телефон, откройте файл и разрешите установку из этого источника.

В релизе лежат два файла — оба подписаны **одним постоянным ключом**, оба ставятся
и обновляются поверх любых предыдущих версий и друг друга:

| Файл | Что это |
|---|---|
| `ArenaMobile-<версия>-build<номер>.apk` | release-сборка: сжата R8 (меньше размер), рекомендуемый вариант |
| `ArenaMobile-<версия>-build<номер>-debug.apk` | debug-сборка: полный набор ресурсов, удобна для отладки |

Обновление: просто установите новый APK поверх старого — данные, профили аккаунтов
и подключения GitHub сохранятся (Android сверяет подпись; `versionCode` растёт
автоматически с каждым запуском CI).

## Что умеет

| Возможность | Как это работает |
|---|---|
| **5 независимых аккаунтов** | Каждый профиль — отдельный процесс Android (`:p1…:p5`) со своим каталогом данных WebView (`app_webview_p1…p5`). Cookie, localStorage и кэш не пересекаются, поэтому вы одновременно залогинены сразу во все аккаунты. |
| **Быстрое переключение** | Тап по аватару в шапке → список профилей. Или кнопка «Продолжить» на главном экране (открывает последний использованный профиль). |
| **Подключение GitHub** | Меню профиля → *Agent Mode / GitHub* (`arena.ai/agent`) → переключатель **GitHub Connector** → OAuth-авторизация. Внутри профиля включены сторонние cookie и файловые загрузки, без которых OAuth не проходит. Логин GitHub автоматически подтягивается в карточку профиля. |
| **Сторонние cookie и вход через Google** | `setAcceptThirdPartyCookies` + режим совместимости (убирает маркер `wv` из User-Agent) — включается в настройках профиля, если провайдер входа отказывается работать внутри WebView. |
| **Версия для ПК** | Отдельный переключатель для каждого профиля: сайт отдаёт десктопную вёрстку (удобно для diff-панели Agent Mode). |
| **Мелкие удобства** | Прогресс загрузки, пункт меню «Наверх страницы», «поделиться/скопировать ссылку», загрузка файлов через DownloadManager, разрешения камеры/микрофона для голосового ввода, диплинки `https://arena.ai/...`, светлая и тёмная темы, запрет выключения экрана во время генерации. |
| **Прокрутка** | Экран профиля — обычный `LinearLayout` без `CoordinatorLayout`, а у `SwipeRefreshLayout` переопределён `canChildScrollUp()`: жест «потянуть вниз» перехватывается только когда страница сама сообщила через JS-мост, что находится в самом верху. Так прокрутка не отбирается у страниц с собственной областью прокрутки (как у arena.ai). |
| **Полный выход из аккаунта** | «Выйти и стереть данные профиля» — удаляет cookies, storage и весь каталог данных профиля, не затрагивая остальные профили. |
| **Самообновление** | Приложение само проверяет свежий релиз на GitHub (тихо при запуске, не чаще раза в 12 часов, и вручную: Настройки → «Проверить обновление»), скачивает APK через DownloadManager и открывает системный установщик. Постоянный ключ подписи гарантирует установку поверх с сохранением профилей и входов. |
| **«Поделиться в Arena»** | Текст из любого приложения (браузера, мессенджера, заметок) → «Поделиться» → Arena: открывается новый чат выбранного профиля, и текст подставляется в поле ввода. Если поле ещё не появилось, скрипт повторяет попытки и в крайнем случае кладёт текст в буфер обмена. |
| **Ярлыки на иконке** | Долгое нажатие на иконку в лаунчере: «Продолжить» (последний профиль) и до четырёх профилей по именам — переключение аккаунта без открытия приложения. |
| **Сохранение входа (автологин)** | WebView сам не сохраняет cookies сессии: при сворачивании приложения они принудительно сбрасываются на диск, а cookies авторизации `arena.ai` продлеваются на год. Включено по умолчанию (Настройки → «Продлевать сессию»). Если вход всё же не пережил перезапуск — приложение один раз об этом скажет. |
| **Диагностика подключения** | Меню профиля → «Диагностика подключения»: показывает, сохранён ли вход, какие cookies на месте, что потерялось с прошлого закрытия, доступны ли `arena.ai`, `github.com` и `api.github.com`, где лежат данные профиля и какая версия WebView. Отчёт копируется одной кнопкой — можно прислать в поддержку. |
| **Блокировка входа** | Настройки → «Блокировка входа»: при запуске приложения запрашивается биометрия или код устройства (через 5 минут в фоне — снова). В приложении лежат активные сессии сразу нескольких аккаунтов, поэтому вход можно закрыть. Пункт меню «Заблокировать сейчас» закрывает приложение немедленно. |
| **Резервная копия профилей** | Настройки → «Экспорт профилей в файл» / «Импорт профилей из файла»: имена, цвета, аккаунты, GitHub-логины и настройки сохраняются в JSON. Cookies не экспортируются осознанно, но после переустановки список аккаунтов восстанавливается одной кнопкой. |
| **Разделы Arena на выбор** | В настройках профиля — «Разделы Arena в меню»: можно оставить только нужные пункты (чат, Agent Mode, рейтинг, история, репозитории, помощь). |
| **Поворот без потери черновика** | Экран профиля не пересоздаётся при повороте (`android:configChanges` в манифесте, проверяется в CI), а если страница всё же перерисовала поле ввода — скрипт-сторож возвращает в него текст и прикреплённые файлы (`composer_keeper.js`) и приложение сообщает: «Черновик возвращён в поле ввода». В отчёте диагностики видно, сколько было поворотов, загрузок страницы и восстановлений черновика. |
| **Свайп по шапке** | Горизонтальный свайп по шапке профиля переключает на следующий/предыдущий аккаунт. Свайп от края экрана не используется — он конфликтует с системным жестом «назад». |
| **Двухпанельный режим** | На планшетах и складных (ширина ≥ 600dp) слева появляется панель профилей: переключение аккаунта одним тапом, без выхода из WebView. |
| **Запуск сразу в профиль** | Настройки → «Открывать сразу последний профиль»: тем, кто пользуется одним аккаунтом, экран выбора больше не мешает. |
| **Тема оформления** | «Как в системе», светлая или тёмная — выбирается в настройках. |
| **Быстрые действия на карточке** | Кнопка ⋮ в карточке профиля: открыть, Agent Mode, «Мои репозитории в GitHub», настройки профиля, очистить кэш, стереть данные. |
| **Очистка кэша без выхода** | Настройки профиля → «Очистить кэш»: удаляются только кэш-каталоги, cookies и входы остаются. Там же видно, сколько места занимает профиль. |

## Обновление приложения

Версия 1.2.0 и новее умеют обновлять себя (в 1.3.0 механизм не менялся):

* при запуске приложение тихо проверяет [последний релиз](https://github.com/zigorminsk-debug/Arena/releases/latest)
  (не чаще раза в 12 часов) и предлагает обновиться, если номер сборки больше;
* вручную — Настройки → **«Проверить обновление»**;
* APK качается через DownloadManager (видно в уведомлениях), затем открывается системный
  установщик. Android один раз спросит разрешение на установку из этого источника;
* обновление ставится поверх: профили, сессии Arena и подключение GitHub сохраняются.

Каналы: в релизе лежат release-APK (сжатый) и debug-APK; приложение предпочитает release.

## Вход в аккаунт и почему иногда просят пароль

Arena внутри WebView ведёт себя как сайт, а не как приложение: cookies сессии
(`__session`, `next-auth.session-token` и подобные) живут **в памяти** и попадают
на диск с задержкой. Профиль работает в отдельном процессе Android, и система
убивает его сразу при закрытии приложения — вместе с ещё не записанными cookies.
Поэтому сайт мог «забывать» вход, и приходилось заново выбирать аккаунт.

Что делает приложение (версия 1.3.0+):

* при сворачивании профиля вызывает `CookieManager.flush()` — cookie-jar
  принудительно записывается на диск до того, как процесс будет убит;
* продлевает cookies авторизации `arena.ai` на год (`Max-Age=31536000`), чтобы они
  стали постоянными и не считались сессионными;
* ведёт «снимок» cookies при закрытии профиля и сравнивает его при следующем
  открытии — это честная проверка «вход пережил перезапуск или нет»;
* если вход не восстановился, один раз показывает подсказку, а подробности
  доступны в меню → **«Диагностика подключения»**.

Если вы всё же видите экран входа Arena — откройте «Диагностика подключения»
в меню профиля:

| Что в отчёте | Что это значит |
|---|---|
| «Вход в Arena: не найден» | Cookies авторизации нет вовсе — нужно войти заново, дальше вход будет держаться |
| «ВНИМАНИЕ: cookie авторизации не пережили перезапуск» | Приложение закрылось до записи cookies: проверьте, что «Продлевать сессию» включено (Настройки), и войдите заново |
| «Изоляция профилей (суффикс WebView): нет» | Профили могли делить cookies — перезапустите приложение (и сообщите об этом, это баг) |
| «arena.ai недоступен из сети» | Проблема не в приложении: проверьте соединение или VPN |

Кнопка **«Продлить сессию сейчас»** в том же окне немедленно переписывает cookies
авторизации с длинным сроком — удобно сразу после входа в аккаунт.

## Автосборка APK (GitHub Actions)

Workflow [`.github/workflows/build-apk.yml`](.github/workflows/build-apk.yml) запускается:

* на каждый push в `main` и `arena/**`;
* на pull request в `main`;
* на push тега `v*`;
* вручную — **Actions → Build APK → Run workflow** (галочка `publish_release`, если нужен Release).

Что делает: ставит JDK 17, собирает debug- и release-APK, проверяет APK
(`aapt2 dump badging`, список профильных процессов, `apksigner verify`), кладёт файлы
в **Artifacts** и (для `main`/тегов/по галочке) публикует **Release** с тегом
`v<версия>-b<номер сборки>`. При ошибке компиляции сообщения Kotlin попадают в
аннотации запуска — их видно, не скачивая логи.

Локальная проверка кода без Android Studio (проверяет ссылки на ресурсы, id и т.д.):

```bash
python3 tools/selfcheck.py          # исходники
python3 tools/check_apk.py dist     # собранные APK: имена для R8, разметки, целостность
```

Юнит-тесты (JVM) — разбор релизов GitHub и сериализация профилей:

```bash
./gradlew :app:testDebugUnitTest
```

### Подпись APK — постоянный ключ

Все APK — и debug, и release — подписываются **одним постоянным ключом**
[`keystore/arena-release.p12`](keystore/README.md) (RSA 3072, PKCS12, действует до 2056 года).
Поэтому любая новая сборка ставится **поверх** уже установленного приложения:
Android сверяет подпись и versionCode, а не только имя пакета.

| Что | Где |
|---|---|
| Ключ | `keystore/arena-release.p12`, алиас `arena`, пароль `arena-mobile` |
| Параметры для Gradle | `keystore/keystore.properties` (читается автоматически) |
| Отпечаток SHA-256 | `F7:11:DD:93:…:4B:A4:AA` — печатается в аннотациях каждой сборки |
| Номер версии | `versionCode = номер запуска CI` (растёт автоматически) |

Подробности и правила безопасности — в [`keystore/README.md`](keystore/README.md).
Если файл ключа удалить, CI создаст новый и закоммитит его сам, но **подпись сменится** —
придётся один раз переустановить приложение на телефоне.

### Свой (приватный) ключ через секреты

Если не хотите держать ключ в репозитории, задайте секреты в
**Settings → Secrets and variables → Actions**:

| Секрет | Значение |
|---|---|
| `KEYSTORE_BASE64` | `base64 -w0 release.jks` |
| `KEYSTORE_PASSWORD` | пароль хранилища |
| `KEY_ALIAS` | алиас ключа |
| `KEY_PASSWORD` | пароль ключа |

Секреты имеют приоритет над файлом в репозитории. Подпись всё равно одна для debug
и release, так что обновления продолжают вставать поверх — но после смены ключа
потребуется одна переустановка приложения.

## Локальная сборка

```bash
# Linux/macOS: JDK 17+ и Android SDK (ANDROID_HOME или local.properties → sdk.dir)
./scripts/build_apk_host.sh            # release APK (сам создаст ключ подписи)
./scripts/build_apk_host.sh debug      # debug APK
# результат в dist/
```

Или обычным Gradle:

```bash
./gradlew :app:assembleDebug
```

Иконки пересобираются из `design/icon_source.png` и `design/icon_mark.png`:

```bash
./scripts/gen_icons.sh     # нужен ImageMagick
```

## Как это работает внутри

* **Изоляция аккаунтов.** Каждой Activity профиля в манифесте задан `android:process=":pN"`,
  а перед созданием WebView вызывается `WebView.setDataDirectorySuffix("pN")` — так каждая
  сессия получает собственные cookie/storage/cache. При выходе из аккаунта отложенная
  очистка сначала гасит процесс профиля, а затем удаляет его каталог данных.
* **Сохранение входа.** Cookies сбрасываются на диск при сворачивании профиля
  (`flush()`), cookies авторизации продлеваются на год, а их список сохраняется в
  снимок — по нему экран «Диагностика» понимает, пережил вход перезапуск или нет.
  Скрипты страницы лежат в `app/src/main/assets/js` и проверяются `node --check`
  в `tools/selfcheck.py`.
* **Приватность.** Никаких сетевых запросов, кроме самих страниц arena.ai и GitHub
  и проверки доступности сети на экране «Диагностика».
  Разрешения камеры/микрофона запрашиваются только при вызове внутри сайта.
* **Ссылки.** `https://arena.ai/...` открываются внутри приложения (диплинк-фильтр),
  остальные схемы (`intent://`, `mailto:`, магазины приложений) передаются системе.

## Если что-то не работает

| Симптом | Решение |
|---|---|
| При каждом запуске просят пароль | Меню профиля → **«Диагностика подключения»**: смотрите, сохранён ли вход. Включите Настройки → **«Продлевать сессию»**, затем войдите заново — с 1.3.0 cookies сессии записываются на диск при сворачивании и продлеваются на год. |
| Забыл пароль от аккаунта в приложении | Профили изолированы, поэтому у каждого свой вход. Войдите один раз в нужный профиль — дальше сессия сохраняется автоматически. |
| Вход через Google не открывается | Настройки профиля → включить **«Режим совместимости входа»**, затем перезагрузить страницу. |
| GitHub Connector не авторизует | Убедитесь, что вы внутри профиля (не в браузере) и что для GitHub разрешён вход в сторонних cookie-контекстах; помогает выход и повторный вход. |
| Сайт выглядит «мобильно сжато» | Включите **«Версия для ПК»** в настройках профиля. |
| Нужно освободить место | Настройки → **«Стереть все профили»** (или по одному: меню профиля → стереть данные). |

## English (short)

**Arena Mobile** is an unofficial Android WebView shell for [arena.ai](https://arena.ai) with
isolated multi-account profiles (one app process + one WebView data directory per profile),
one-tap account switching, GitHub OAuth support for Agent Mode, desktop mode, downloads,
camera/mic permissions and deep links. APKs are built automatically by GitHub Actions —
see [Releases](../../releases). Build locally with `./scripts/build_apk_host.sh`, or check the
sources statically with `python3 tools/selfcheck.py`. MIT-style use at your own risk; not
affiliated with Arena.
