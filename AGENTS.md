# Инструкции для агентов и для работы в свежем клоне

Короткий свод правил, чтобы проект **всегда** собирался, а подпись APK не менялась —
независимо от того, в каком окружении и каким агентом ведётся работа.

## 1. Первым делом — проверить воркспейс

Бывает, что рабочая копия приходит в неконсистентном состоянии: ветка есть, но указывает
на служебный `Initial commit`, а проект лежит в удалённой ветке (в дереве нет `gradlew`,
`app/`, `keystore/`). Сборка в таком воркспейсе невозможна.

```bash
bash tools/bootstrap_workspace.sh --check      # только проверить (exit 1, если надо синхронизировать)
bash tools/bootstrap_workspace.sh              # синхронизировать; файлы в дереве не удаляются
bash tools/bootstrap_workspace.sh --force      # жёстко: состояние GitHub, правки уходят в git stash
```

Скрипт безопасен по умолчанию: `git fetch` + `git reset --mixed` (коммит и индекс приводятся
к GitHub, файлы остаются как есть), поэтому незакоммиченная работа видна в `git status` и не теряется.
После синхронизации — `git add -A && git commit && git push origin <ветка>`.

## 2. Ветки и ветка main

* Сессия Arena работает в ветке `arena/<id>`; все изменения коммитьте туда и пушьте туда же.
* **`main` — это витрина проекта: в ней всегда должна лежать последняя законченная работа.**
  Пустой `main` означает, что чистый клон репозитория не содержит ни кода, ни ключа подписи,
  ни автосборки. Поэтому законченную работу вливайте в `main` через pull request.
* Теги `v<версия>` выпускаются по мере готовности и превращаются в GitHub Release с APK.

## 3. Ключ подписи — не менять

Все APK подписаны одним постоянным ключом `keystore/arena-release.p12`
(алиас `arena`, пароль `arena-mobile`, отпечаток SHA-256 `F7:11:DD:93:…:4B:A4:AA`).
С другим ключом Android не поставит обновление поверх установленного приложения.

* Ключ лежит в четырёх местах: файл в ветке, тег `signing-key-v1`, ассеты релиза
  `signing-key-v1`, секреты репозитория. Подробности — [keystore/README.md](keystore/README.md).
* Новый ключ создаётся **только** запуском workflow с `rotate_key = true`, и это означает
  одноразовую переустановку приложения у всех.
* Не удаляйте `keystore/`, тег `signing-key-v1` и релиз с ним; `tools/selfcheck.py`
  и CI падают, если ключ или защита подписи пропали.

## 4. Сборка

Сборка всегда выполняется в GitHub Actions (`.github/workflows/build-apk.yml`):

* push в ветку `arena/**` → артефакт `ArenaMobile-APK-…` во вкладке Actions;
* push в `main` и теги `v*` → GitHub Release с APK;
* номер сборки (`versionCode`) — это номер запуска CI, имя версии берётся из `version.properties`.

Локально сборка возможна только при наличии JDK 17 и Android SDK:
`./scripts/build_apk_host.sh`. В песочнице без сети к Maven используйте CI.

## 5. Перед каждым пушем

```bash
python3 tools/selfcheck.py        # разметки, строки, ресурсы, манифест, ключ, workflow
node --check app/src/main/assets/js/*.js   # если правили скрипты страницы (это же делает selfcheck)
```

Проверки, которые выполняет CI (все должны быть зелёными): `selfcheck.py` → юнит-тесты и
сборка debug+release → `tools/test_report.py` → `tools/check_apk.py` (имена для R8, разметки,
манифест) → `tools/check_manifest.py` (флаги `configChanges` в собранном APK) → сверка
отпечатка подписи → публикация релиза.

## 6. Пользовательские тексты и документация

* Интерфейс и документация — на русском, английские строки дублируются в `values/strings.xml`.
* Изменения, заметные пользователю, описывайте в [CHANGELOG.md](CHANGELOG.md) и в описании релиза.
* План развития и «что сознательно не делаем» — [IMPROVEMENTS.md](IMPROVEMENTS.md).

## 7. Смена машины, форка или владельца репозитория

Ссылка на репозиторий для самообновления приложения берётся из `BuildConfig.GITHUB_REPO`:
CI подставляет её из переменной `GITHUB_REPOSITORY` (`-Prepo=…`). В другом репозитории
сборка автоматически укажет самообновление на себя; для локальных сборок используется
значение по умолчанию из `app/build.gradle.kts`.
