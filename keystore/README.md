# Постоянный ключ подписи

`arena-release.p12` — постоянный ключ, которым подписываются **все** APK: и debug, и release.
Благодаря этому любая новая сборка устанавливается поверх уже установленного приложения
(Android сверяет подпись, а не только имя пакета).

| Параметр | Значение |
|---|---|
| Файл | `keystore/arena-release.p12` |
| Тип хранилища | PKCS12 |
| Алиас ключа | `arena` |
| Пароль хранилища и ключа | `arena-mobile` |
| Алгоритм | RSA 3072, SHA-256 |
| Действует до | 09.09.2056 (30 лет с 17.09.2026) |
| SHA-256 отпечаток | `F7:11:DD:93:7B:D6:A8:C7:A4:3A:8D:9C:C3:4F:54:E7:02:E9:4D:A6:4B:7F:17:5C:D1:C5:75:CD:11:4B:A4:AA` |
| SHA-256 файла ключа | `68ab31ff8da13cc623915fc65180f69d205779dc5f36c8a882616d83e0ed2aee` |

Посмотреть отпечаток установленного APK:

```bash
keytool -printcert -jarfile ArenaMobile-*-debug.apk            # через JAR-подпись
apksigner verify --print-certs ArenaMobile-*-debug.apk        # через apksigner
```

## Ключ хранится в четырёх независимых местах

Ключ обязан пережить смену ветки, пересоздание рабочей копии и смену агента/сессии,
который собирает APK. Поэтому он лежит сразу в нескольких хранилищах:

| Место | Как достать | Когда спасает |
|---|---|---|
| `keystore/arena-release.p12` в ветке | `git show <ветка>:keystore/arena-release.p12` | обычная сборка: CI берёт ключ отсюда |
| тег `signing-key-v1` | `git fetch origin tag signing-key-v1` → `git show signing-key-v1:keystore/arena-release.p12` | ветку удалили, переписали или работа идёт из другого места |
| релиз `signing-key-v1` (ассеты) | `gh release download signing-key-v1 -p arena-release.p12` | git недоступен; удобно человеку |
| секреты репозитория `KEYSTORE_BASE64` и др. | Actions → Secrets → New secret | если файл ключа убрали из репозитория |

Подробная инструкция по восстановлению — в [KEY-RESTORE.md](KEY-RESTORE.md) (этот же файл
публикуется как описание релиза `signing-key-v1`).

## Что делает CI

Шаг «Ключ подписи» ищет ключ в порядке: секреты → файлы ветки → тег `signing-key-v1` →
ассеты релиза → **только при `rotate_key = true`** создаёт новый. Если ключа нет нигде,
сборка останавливается с ошибкой: молча созданный ключ сломал бы обновления.

Дальше две проверки не дают выпустить APK с чужим ключом:

* до сборки — `keytool` сверяет отпечаток найденного ключа с постоянным;
* после сборки — `apksigner` сверяет отпечаток готового APK (и debug, и release между собой).

Шаг «Резервная копия ключа подписи» поддерживает ассеты релиза `signing-key-v1` в
актуальном состоянии, чтобы резервная копия не устарела.

## Важно про безопасность

Ключ лежит в репозитории открыто — вместе с паролем. Это удобно (сборка работает
без настройки секретов), но означает, что любой, у кого есть доступ к репозиторию,
может подписать APK этим ключом. Для личного приложения это нормально; если нужен
приватный ключ — см. блок «Свой ключ» в README: положите keystore в секреты
`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`, и он получит приоритет.
Тогда этот файл можно удалить из репозитория, но **после этого придётся один раз
переустановить приложение** — подпись сменится.

## Потеря или замена ключа

Ключ обязателен для обновлений: если подпись изменится, Android не даст установить
новую версию поверх старой. Поэтому файл нельзя удалять из репозитория — просто
не меняйте его. Если ключ утерян, единственный путь — новый ключ и одноразовая
переустановка приложения на телефоне. Порядок осознанной замены — в
[KEY-RESTORE.md](KEY-RESTORE.md).
